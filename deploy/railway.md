## Сборка и запуск

- Источник: репозиторий [`pointpu/baselounge`](https://github.com/pointpu/baselounge), ветка `main`.
- Сборка: существующий `Dockerfile`; Mini App собирается Vite внутри образа.
- Pre-deploy: `node src/server/goose.ts` — применяет миграции до запуска приложения.
- Start: `node src/server/main.ts` — API, Mini App и Telegram-бот в одном процессе.
- Healthcheck: `/healthz` — проверяет соединение с PostgreSQL через `SELECT 1`.
- HTTP-порт: `8000`.
- Оба сервиса в регионе `sfo`; приложение: одна реплика, без сна,
  overlap `0` секунд, draining `10` секунд.

В runtime-образе нет npm, поэтому команды Railway вызывают Node напрямую.
Не запускайте второй экземпляр бота с тем же токеном: long polling требует одного получателя.

## Резервные копии в свой S3

Настроен отдельный сервис `postgres-backup`; первый успешный запуск — 8 ноября 2026,
19:52 МСК. Созданы и проверены дневной, недельный и месячный архивы по 22 844 байта.
Код контейнера — ветка `codex/railway-s3-backups`, коммит `76850f7`, папка `/deploy/backup`.
Ветка `main` приложения не изменялась. PostgreSQL 18 создаёт логический архив;
после проверки и выгрузки контейнер завершается.

| Настройка | Значение |
|---|---|
| Расписание Railway | `0 0 * * *` — ежедневно в **03:00 по Москве** |
| Хранилище | Yandex Object Storage, бакет `baza-backup` |
| Endpoint | `https://storage.yandexcloud.net` |
| Регион S3 | `ru-central1` |
| Префикс | `baselounge/postgres/` |
| Адресация S3 | `path` |
| Подключение к БД | `${{Postgres.DATABASE_URL}}` |
| Ключи S3 | Только в переменных сервиса Railway; в Git не сохраняются |

Ежедневные копии хранятся 6 дней, недельные — 27 дней, месячные — 89 дней.
Недельная копия создаётся в воскресенье, месячная — первого числа; при первом
запуске инициализируются все три периода. Для каждого периода всегда сохраняется
хотя бы один архив. Перед очисткой задача сверяет размер и SHA-256,
скачивает дневной архив обратно и проверяет его каталог через `pg_restore --list`.
Это проверка целостности; полное пробное восстановление отдельно не выполнялось.
Версионирование бакета при настройке выключено; очистка удаляет устаревшие объекты.
Deployment успешного запуска: `d3bae42e-a762-4e0d-9682-c8460d0f57be`.

Настройки, необходимые права и порядок восстановления описаны в

сделайте резервную копию БД. После обновления проверьте deployment logs,
`/healthz` и открытие Mini App из Telegram.
